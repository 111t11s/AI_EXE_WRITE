# 墨间 · 小说工作台

大纲技能已从历史资料蒸馏到 [agents/skills](agents/skills)，`meterials` 原始资料目录由用户自行管理，运行时不会读取。每个技能独立存放于 `agents/skills/<技能名>/SKILL.md`，包含 `name`、`description` 元数据和技能正文。选择小说类型后，问答页会显示已加载的技能；生成世界观蓝图及已有小说的新大纲时，后台根据当前类型读取技能正文。玄幻、都市、武侠、仙侠、历史分别加载专项技能和通用技能，修真／修仙匹配仙侠，架空历史匹配历史；混合类型按出现顺序组合，单独的“架空”不默认匹配历史，科幻等暂无专项资料的类型使用通用技能。用户设定、篇幅、卷数及已有世界规则优先。

技能目录中的 `SKILL.md` 可直接维护，无需数据库迁移；部署时需包含 `agents/skills` 目录。资料校验值、去重关系及提炼取舍见 [来源清单](agents/skills/sources.json)；来源清单只作历史溯源，运行时不读取原始资料。接口 `GET /api/v1/novel-assistant/outline-skills?genre=玄幻` 可查询当前加载信息，需登录。

从项目根目录启动现有 Python 环境中的应用：

```powershell
.\.venv\Scripts\python.exe -X utf8 main.py
```

本机打开 [http://127.0.0.1:8001/](http://127.0.0.1:8001/)（项目 `.env` 配置的端口）。如果改过端口，请打开终端里「工作台」后面的链接。页面由 FastAPI 一并提供，无需另启前端服务。项目读取与保存使用 `.env` 里的 MySQL 配置；生成与审读还需要当前 CrewAI 环境和可用的模型配置。

模型名称和可选模型列表统一维护在 `core/model_config.py`，由 `main_model` 标记默认主模型。环境变量提供访问密钥和服务地址：GPT 使用 `GPT_API_KEY`（兼容旧配置 `API_KEY`）与 `GPT_BASE_URL`，Gemini 使用 `GEMINI_API_KEY` 与 `GEMINI_BASE_URL`，DeepSeek 使用 `DEEPSEEK_API_KEY` 与 `DEEPSEEK_BASE_URL`。部署时请在 `.env` 中填写对应服务地址；`deployment/.env.example` 提供了默认地址示例。`GET /api/v1/models` 返回可用模型清单，不会下发密钥或服务地址；界面提交模型 ID，未传 `model` 时使用 `main_model` 对应的模型。

左侧栏的「文件选题」支持上传 TXT、Markdown、DOCX（最多 5 个，单个 10MB，总读取约 6 万字符），也可以直接粘贴文本（上限 25,000 字符）：后台任务读取材料，提炼题材类型、人物关系、核心冲突、读者情绪与可传播话题，输出 3—5 个可直接开写的原创方案（类型、背景、力量体系、金手指、主角、目标、基调、篇幅、书名、卖点、话题点、风险）。上传文本只用于本次分析，不写入小说项目，也不会照搬原有人物、情节或原文。推荐卡的「用此题材新建小说」会预填问答的 8 项基础设定，仍可继续调整。接口为 `POST /api/v1/document-topics/analyze/tasks`（multipart：`files`、`text`、`instruction`、`genre_preference`、`audience`、`idea_count`、`model`），任务类型为 `topics`，报告保存在任务中心；预填接口为 `POST /api/v1/novel-assistant/sessions/{id}/prefill`。分析结果保存到 `app_document_topic`，可在「文件选题」页的历史选题中查看；升级数据库需由数据库管理员导入 `deployment/document-topics.sql`。文件格式不支持或解析失败时页面会提示；nginx 的 `client_max_body_size` 需不小于 55MB，并安装 `python-multipart`。
左侧栏的「小说拆解」是专门的小说章节分析智能体：上传 TXT、Markdown、DOCX 章节，或直接粘贴章节正文（上限 25,000 字符）后，按人物构造、职介构造、世界构造、剧情构造、文笔写法五个维度提取可复用技法。它只分析上传文本，逐条给出原文证据、写法机制和复用方法；材料不足的维度会标记为不可分析，不推断未写出的设定。每张技法卡包含名称、摘要、机制、复用方式、证据、置信度和适用类型。接口为 `POST /api/v1/novel-analysis/analyze/tasks`，结果保存到 `app_novel_analysis`，可在「小说拆解 → 写作技法库」中跨小说查阅、复制；升级数据库需由数据库管理员导入 `deployment/novel-analysis.sql`。技能文件为 `agents/skills/novel-analysis/SKILL.md`，由 `NOVEL_ANALYST` 智能体加载。
小说拆解支持自我进化：固定五维之外的写法会作为新维度候选存入 app_analysis_candidate；审核通过后写入 app_analysis_technique，并把该维度加入 app_analysis_dimension，后续拆解会自动带上这个扩展维度。候选审核在「小说拆解 → 技法审核」中完成。
文件选题页还提供「补充世界观」：把粘贴或上传的文本当作既定设定，直接补全世界总览、力量体系、职介体系、社会日常、势力冲突和剧情钩子；不重新拆题、不替换核心概念。接口为 POST /api/v1/document-topics/expand/tasks，结果保存到 app_setting_expansion，可在同页「设定补全历史」查看。
审核通过的技法按世界观构造、大纲、正文三类归入知识库；新建或重写大纲时只能选择前两类，生成、重写、润色、续写正文时选择正文类，选中的技法会作为参考注入对应生成任务。

首次升级需执行账号迁移，详见 [账号与旧小说迁移](deployment/README.md#账号与旧小说迁移)。普通账号登录后只显示自己的小说；新建小说自动绑定登录账号。密码使用加盐 scrypt 哈希，登录状态可退出注销，默认有效期为 7 天。

管理员可查看全部账号的小说，按所属账号筛选，阅读和导出正文、大纲与角色档案。其他账号的小说只读，自己的小说仍可创作。需迁移 `app_account.is_admin` 并在服务器执行 `python -m db.manage_admin 用户名 --create` 显式创建或授权；无默认密码，注册不能获取管理员权限，详见 [部署说明](deployment/README.md#管理员查看全部账号小说2026-11-15)。

登录后可在账号栏修改密码；忘记密码时由服务器管理员运行 `python -m db.reset_password 用户名`，交互输入新密码。修改或重置都会撤销该账号全部登录会话，详见 [密码重置说明](deployment/README.md#修改与重置密码)。

生成请求以后台任务运行，项目页不展开任务进度；任务完成后会在左上角短暂提示“任务完成，请去任务中心查看”，可通过“任务中心 → 查看进度”查看实时进度与生成结果；进度页展示模型思考过程，但会把思考中的结构化参数名和枚举值转成中文，不直接显示 chapter 这类英文参数；大纲、角色、一致性等结构化生成在完成前只显示中文进度提示，完成后展示中文结果。任务中心包含“全部任务、世界观、大纲、正文、角色、章节规划、审读、一致性核对、选题、拆解”等子菜单，每类显示生成中的任务数量；任务还可按小说筛选，便于区分不同书籍的大纲和其他生成记录。默认显示当前账号所有小说中正在生成的任务，可切换全部状态、已完成或未完成；每 4 秒自动刷新，全部状态下生成中的任务优先显示。任务列表由服务端按分类、小说和状态筛选后分页返回，页大小 5/10/20 可选，筛选计数（分类、小说、状态）也由服务端计算。关闭进度页或刷新浏览器后仍可回来查看，完成后可打开已保存结果。小说移入回收站时，其后台任务和进行中的生成会一并清理。任务记录保存在数据库（`app_generation_job`），服务重启后自动恢复，不再按时间或数量自动清空：可在任务中心逐条删除，或勾选多条后点「删除所选」；生成中的任务需完成后再删除，删除记录不影响已保存的小说内容。

从个人书架打开小说，查看当前世界观，然后：

1. 新建小说时，世界观生成会同时创建第一卷大纲、唯一的一位男主和一位女主，并按第一卷大纲保存两人的阶段档案。已有项目若还没有男女主，可在「角色」创建一次；之后只能按大纲补充配角。
2. 在「大纲与分卷」生成一个版本，选中一卷查看剧情节点，点击「生成本卷配角」；也可在「角色」选择大纲版本后点击「根据大纲补充配角」，再选择目标卷。第二卷起可勾选前卷配角安排新戏份；新增数量设为 0 可只复用旧配角。
3. 点击「规划章节」，选择起始章号和章节数。起始章号默认取全书下一个可用章号（最大章号 + 1），章号在全书内唯一，与已用章号范围重叠时会在生成前提示可用章号。本卷已有生成正文的章节时不再显示该入口；仅规划、还没有正文的分卷仍可继续规划。
4. 在「章节与正文」选中一章，生成初稿或手动编辑，再点击「审读本章」。生成前会检查角色信息；没有角色时会打开角色生成设置，由你选择数量并生成，完成后再写正文。审读建议不改动正文，刷新页面后不保留。

大纲详情的「重写大纲」基于当前选中的版本、完整分卷与剧情节点、角色和世界观重写，可设置修改要求及卷数；结果保存为新版本，原版本、已有章节和原卷角色戏份保留，章节不会自动迁移到新卷。已有正文的章节显示「重写正文」，可设置修改要求及目标篇幅；成功后替换本章正文并恢复草稿状态，清除页面中的旧审读建议。模型失败或保存前发现章节原文、标题、摘要、所属卷或状态已变化时不覆盖章节。两种重写均支持后台任务与实时进度，无需新增数据库迁移。

重写 API：`POST /api/v1/writing/outlines/{outline_id}/rewrite`（`OutlineRequest`），`POST /api/v1/writing/chapters/{chapter_id}/rewrite`（`DraftRequest`）；追加 `/tasks` 提交后台任务，追加 `/stream` 获取 SSE。

正文生成和重写向模型请求纯文本正文，保留段落换行，也兼容原有 `{"content":"正文"}` JSON 输出。正文仍需通过 100–30000 字符校验；损坏的 JSON、未闭合的代码围栏，以及模型明确报告超限或中途截断的输出不会保存。批量生成先按章序保存全部选中章节的正文，再统一分析并更新各章人物进展；角色、章节规划、审读等任务继续使用原有 JSON 校验。

小说标题区域的「导出小说」下载 ZIP 压缩包，每章一个 TXT 或 Markdown 文件，文件名如 `第00001章_启程.txt`。可导出全部已保存正文，或选择「选择章节」跨页勾选、全选本页、清空选择后批量导出。章节按全书章号排序，保留分卷标题和段落，跳过空正文，不受最新大纲版本限制；附带的完整大纲、分卷及剧情节点单独存为 `大纲-v1.txt`（或 `.md`）。TXT 使用带 BOM 的 UTF-8 编码，Markdown 保留标题层级。没有正文时可选择大纲单独导出；生成中尚未保存的内容不包含在压缩包中。普通账号可导出自己的小说，管理员可导出全部小说；导出不调用模型，不修改数据库，无需数据库迁移。

全部导出 API：`GET /api/v1/projects/{project_id}/export?format=txt`；批量导出 API：`POST /api/v1/projects/{project_id}/export`，JSON 如 `{"format":"txt","chapter_ids":[1,3,5]}`，避免大量章节 ID 超出网址长度限制。`format` 可为 `txt` 或 `md`，可选 `outline_id` 附带指定大纲。GET 也支持重复的 `chapter_ids` 参数。所有请求需携带账号的 `Authorization` 请求头，返回 `application/zip` 附件及中文文件名。所选章节不属于该小说或已被删除时返回 404，不会部分导出或退回全书导出。
5. 在「一致性核对」选择对照大纲版本，跨页勾选需要阅读的章节，点击「核对所选章节」。任务在后台运行，通过「查看进度」查看实时内容及核对报告。

角色生成智能体通过 MCP 读取当前世界观、力量规则、势力及已有角色；补充配角时还读取所选大纲的分卷、剧情节点和前卷戏份。新人物保存到角色表，复用人物沿用原 ID，本卷新戏份单独保存到 `novel_volume_character`，并供章节规划和正文生成使用。在分卷详情可查看人物阶段计划。已有数据库升级需执行 `python -m db.migrate_volume_characters`，新库直接导入最新版 SQL。同名、人数或复用 ID 校验失败时整批不保存；已有角色档案与前卷戏份不会被覆盖。旧角色简介明确写出前卷标题时，也可在后卷勾选复用。实时生成内容在任务的「查看进度」页面展示，完成后可直接打开角色档案。

正文生成和重写只保存正文；人物进展由单独分析任务提取实际行动、状态和关系，并核对正文原句后写入 `novel_character_progress`。批量生成会先保存全部章节正文，再逐章分析进展；某章分析失败不会回滚正文或中断其他章节，任务结果会列出未更新的章节。在「角色」展开人物，可查看「正文进展（已发生）」及原句，与基础设定和大纲阶段计划分开展示。后续章节通过 MCP 读取此前每位人物最近的进展，不带入未来状态。重写或手工修改正文、章号、所属分卷会清除该章旧进展；删除章节会级联删除。单独运行「分析人物进展」时会跳过无法核实的角色，保存其余角色并提示；全部角色都无法核实时保留原档案。升级已有数据库须先运行 `python -m db.migrate_character_progress`；应用缺少 CREATE 权限时用数据库管理员导入 `deployment/character-progress.sql`。

一致性核对智能体仅在用户发起时读取所选章节的完整正文，结合所选大纲、人物档案、世界规则判断剧情、人物、设定及章节衔接是否偏移。每次 1–20 章，正文总计最多 120000 字符；无正文的章节不可选择。问题附章节原文、对照资料原文、偏移说明及修正建议，程序核验引文真实存在于本次读取资料。引文核对按问题逐条进行：无法在所选正文或档案中逐字匹配的问题会被忽略，并在报告的限制中注明条数；若报告声称发现偏移但全部问题都无法核对，结论改为“资料不足”，不再让整次核对失败。报告中的问题按条翻页查看，可勾选多条后「采纳所选」，或「一键采纳全部」；批量采纳只启动一个后台修复任务，按问题顺序修复，个别问题失败不影响其他问题。结论区分“未发现明确偏移”“发现偏移”和“资料不足”，不连续章号会注明范围限制，不对未读章节或全书作判断。核对不修改正文、人物和大纲；报告保存在任务中心（`app_generation_job`），随任务记录一起保留或删除，无需新增 SQL。

核对前强制通过 MCP 读取已保存的完整大纲、分卷节点与角色戏份、人物档案及人物关系，以及地域、力量体系和等级、金手指、势力档案。报告展示实际读取的档案清单；每个问题必须引用本次读取资料中的真实字段原文，不接受工作流状态或同章正文自证矛盾。档案未记载、缺少对应时期信息或未选章节中的事件均不能凭常识或类型惯例判定为偏移，资料不足须说明限制。人物关系只能从本小说角色间的关系记录中读取。

一致性报告中的每条修复意见可通过「编辑修复意见」保存修改，也可在「采纳并修复」时调整后直接提交。采纳后启动后台修复任务，只改该问题的正文依据所引用的章节，完成后替换正文并保存为草稿，可从任务中心查看进度和打开对应章节。一个问题涉及多章时，全部生成成功且原文校验通过才一并保存；核对后手动编辑过的章节不会被覆盖，需重新核对。可继续采纳其他意见；如果此前修复已改变该意见的原文依据，需要重新核对。修复会清除对应章节的旧人物正文进展，可另行重新分析。修复意见及采纳状态随原报告保留，无需新增 SQL；旧报告需重新核对后才能使用修复入口。

角色阶段档案按大纲版本和分卷记录「本部分行动」「阶段结果」「与小说进度的关系」，并关联真实剧情节点。新建小说时会按自动生成的第一卷大纲创建男女主及其阶段档案；之后按大纲新增或复用的角色均为配角，并保存对应档案。仍可从角色卡片或分卷入口为已有角色补写阶段档案，每次最多选择 20 位。角色页切换大纲版本查看相应分卷记录；当前写作进度从保存的正文实时计算，阶段结果始终表示大纲计划，不把尚未写出的行动或结局当作事实。后续正文生成和一致性核对会读取这些阶段档案，沿用现有分卷角色戏份表，无需新增 SQL。

也可以点「新建小说」，通过问答生成并保存世界观。接口见 [Swagger](http://127.0.0.1:8001/docs)，MCP 接入见 [工具说明](agents/mcp/README.md)。如果端口已被占用，可在 PowerShell 先执行 `$env:PORT='8002'` 再启动，页面地址改用 `8002`。通过 `main.py` 启动时，内部 MCP 连接默认跟随该端口；如果已经配置了 `AITXT_API_BASE_URL`，请让它指向同一个 API。
